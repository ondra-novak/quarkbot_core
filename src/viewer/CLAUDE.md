# QuarkBot Viewer — Claude Context

Browser-based backtest report visualizer. Reads `.jsonl` report files generated by
`src/quarkbot/backtest/json_report.cpp` and shows an interactive TradingView-style chart.

**The viewer is mid-rewrite.** A second, older implementation still lives in the tree and is
deliberately kept — see [Disconnected code](#disconnected-code-kept-on-purpose). Do not delete it
and do not "fix" it into the build; it is reference material for features not yet ported.

## Quick start

```bash
cd src/viewer
npm install

# dev: vite on :5173 proxies /api → :3001, so the API server must run on 3001
node server.js ../../report.jsonl -p 3001 &
npm run dev

# production: build once, then serve
npm run build                       # vue-tsc --noEmit && vite build → dist/
node server.js ../../report.jsonl   # random free port, prints the URL
```

The dev proxy targets **3001**, not 3000, because 3000 was taken on a dev machine (Grafana, an
earlier attempt at visualizing this data). The port lives in `vite.config.ts` → `server.proxy`.

```bash
npm test                            # vitest run — see Tests below
npx vitest run src/types/options.test.ts
```

## Stack

- **Vue 3** (`<script setup>`, TypeScript) + Vite
- **lightweight-charts v5.2** — v5 has native multi-pane support (`addSeries(..., paneIndex)`),
  which v4 lacked. The rewrite exists largely to use it.
- **vitest** for unit tests
- Node.js HTTP server (`server.js`) — serves `dist/`, the report, and the options profile

## server.js

```
Usage: node server.js <path-to-report.jsonl> [options]

  -p, --port PORT           HTTP port (default: a free port picked by the OS)
  -P, --profile PATH        options profile file
  --no-save                 serve read-only: do not persist viewer options
  -h, --help                show this help
```

Arguments are parsed from the `SPEC` table at the top of the file; **adding a flag means adding one
row there**, and `--help` is generated from it. `--flag=value`, `--flag value`, `-f value`, `--`,
and bare positional arguments all work; an unknown flag is a hard error.

| endpoint | method | behaviour |
|---|---|---|
| `/api/report` | GET | streams the `.jsonl` file with `Content-Length` (drives the load progress bar) |
| `/api/options` | GET | `200` + profile JSON, or **`204`** when no profile exists yet or it is unreadable |
| `/api/options` | PUT | stores the JSON body; `400` invalid JSON / not an object, `413` over 1 MB, `204` OK |
| anything else | GET | file from `dist/`, else `index.html` (SPA fallback) |

The profile write is **atomic** (`.tmp` + `rename`) because the client saves on every change; a
truncated write would otherwise lose the profile. A corrupt profile on disk yields `204` plus a
warning on stderr — it must never stop the viewer from starting.

Profile location, first match wins:

1. `--profile PATH`
2. `$QUARKBOT_VIEWER_PROFILE`
3. `$XDG_CONFIG_HOME/quarkbot_viewer/options.json`
4. `~/.config/quarkbot_viewer/options.json`

## JSONL format

One JSON array per line: `[unix_seconds, nanoseconds, event_type, payload]`. The first two fields
are a split nanosecond timestamp, **not** a sequence number; the client folds them into
milliseconds (`sec * 1000 + nsec / 1e6`). Emitted by `JsonReport::out()`.

| type | payload | meaning |
|------|---------|---------|
| `I` | `{name, leverage, type, multiplier, tick_scale, lot}` | instrument registration (first) |
| `C` | `{interval}` | base candle interval **in minutes** |
| `c` | `[name, open, high, low, close, volume, start_time]` | OHLC bar; `start_time` is unix **seconds** and is the bar's *start* |
| `f` | order fields + `{id, label, side, price, quantity, reason}` | fill |
| `s` | order fields + `{filled, turnover, fees, fees_native}` | fill stats summary |
| `o` | order fields + `{status}`, plus `{rejected_reason, reject_text}` on rejection | order state update |
| `v` | `{name, rev: [ordered, random], val}` | strategy variable snapshot |

"Order fields" (shared by `f`, `s`, `o`) are
`{instrument, order_id, type, side, quantity}` plus `limit_price` for limit orders, `stop_price`
for stop orders, and `replaced_order_id` when the order replaced another one.

Variable names arrive namespaced, e.g. `BTCUSD::ema_master`.

## Architecture (the connected code)

```
main.ts
 └── App.vue                     state hub: report + options + profile persistence
      ├── LoadProgress.vue       progress bar / error surface during load
      ├── TopBar.vue             instrument select, timeframe buttons, toggles (Fills / Ords / Vol)
      │    └── SeriesSelector.vue    assigns series to panes
      │         └── SeriesItemEditor.vue   per-series color + line style
      └── Chart.vue              single lightweight-charts instance, all panes
           └── order_lines.ts    order-instance overlay (canvas primitive)
```

Supporting types in `src/types/`:

| file | purpose |
|---|---|
| `report_types.ts` | wire-level types mirroring the JSONL payloads |
| `parsed_report.ts` | `ParsedReport.load()` — streaming JSONL parse + derived series |
| `options.ts` | `DisplayOptions`, `default_options()`, `sanitize_options()` |
| `profile.ts` | loads/saves options via `/api/options` |
| `contract.ts` | `calculate_pnl()` / `calculate_turnover()`, incl. inverse contracts |
| `constants.ts` | `side_value` (buy `+1` / sell `-1`) |
| `stringToColor.ts` | stable color from a series name |

### Data flow

`App.vue` `onMounted`: `load_options()` → `nextTick()` → enable autosave → `load_data()`.
`load_data()` fetches `/api/report` and hands the `ReadableStream` to `ParsedReport.load()`, which
parses line by line and reports bytes read for the progress bar. There is **no web worker** in this
path (the old implementation had one — see below).

`ParsedInstrumentReport.recalc()` derives, from the raw events:

- `eq_chart` / `pos_chart` — realized P&L and position, walked over `fills` via `calculate_pnl()`
- `order_instances` — `order_updates` carrying a `limit_price` or `stop_price`, grouped by
  `order_id`; `start`/`end` are the min/max update time of the group

A replace produces a **new `order_id`**, so a replace chain shows up as several short instances
rather than one long one. `OrderUpdate.replaced_order_id` is the link if they ever need joining.

### Options persistence

`DisplayOptions` is the whole persisted state (instrument, timeframe, toggles, pane assignment,
per-series color/style). `App.vue` watches it deeply and calls `save_options()`, which coalesces
writes 500 ms apart and flushes on `pagehide` with `keepalive`. The debounce timer is deliberately
**not** reset on each change, so dragging a color picker still writes within 500 ms.

`sanitize_options()` is the trust boundary for the on-disk profile: missing keys come from
defaults, unknown keys are dropped, wrong types fall back. Note the asymmetry — pane names are
validated against `paneTypes`, but `setup` entries are validated only by *shape*, because variable
names cannot be known ahead of time. That is what lets a variable keep its color across strategies,
at the cost of accumulating dead entries (delete the profile to reset).

One global profile serves all reports; a stale `instrument` or `interval` is harmless because
`App.vue` falls back via `get_default_instrumnet()` and `Math.max(interval, baseInterval)`.

### Order lines overlay (`order_lines.ts`)

`OrderLinesPrimitive` is a lightweight-charts **series primitive** attached to the candlestick
series, drawn on a raw canvas — v5 series are time-indexed (one value per time point), so hundreds
of thousands of independent segments cannot be modeled as series at all.

One horizontal line per order instance: left edge of the first bar to the right edge of the last,
at the order price. Buy `#26a69a` / sell `#ef5350`; limit solid (a wall), stop dashed (it reacts to
price falling through). Colors are hardcoded on purpose — the overlay is read as a *swarm*, to see
which orders price reached and which it did not, so there is nothing to look up in a legend.

Performance shape, with ~140 000 instances in mind:

- times are mapped to **bar indices** once per timeframe change, not per frame, and not to pixel
  positions — the axis is positioned by index, so gaps in the data would otherwise drift the lines
- data lives in typed arrays sorted by start bar; the visible window is a binary search
- instances are split into **short** and **long** (> 512 bars) buckets. A single order living for
  weeks would otherwise force the binary search to over-reach by its whole span and degrade into a
  full scan — real reports contain exactly such outliers.
- above **20 000** visible segments the layer stops drawing (`MAX_VISIBLE`); at that zoom it is an
  unreadable smear anyway and it returns on zoom-in
- drawing batches into one `stroke()` per direction×type, not per segment

## Tests

`src/types/options.test.ts` covers `sanitize_options` / `default_options` (16 tests) and passes.
`src/utils/aggregator.test.ts` belongs to the disconnected code and **fails to compile** — run
tests for a specific file rather than the whole suite until that is resolved.

Likewise `vue-tsc --noEmit` reports a stable baseline of errors, all inside the disconnected files.
When checking your own work, compare the count against that baseline rather than expecting zero.

## Disconnected code (kept on purpose)

These are the previous implementation, retained as a reference for features not yet ported —
analytics especially. Most of them import `./types/report`, a module that no longer exists, so they
do not compile; `aggregator.ts` is an empty file, which is why importing it reports "is not a
module"; `PanelBar.vue` compiles fine and is merely unreferenced.

| file | what it holds |
|---|---|
| `src/App copy.vue` | old state hub, worker-driven |
| `src/components/ChartView.vue` | old multi-chart panel stack (v4 had no panes, so each panel was a separate `createChart()` with synced time scales) |
| `src/components/StatsPanel.vue` | per-instrument stats panel |
| `src/components/FillDetail.vue` | fill table modal on candle click |
| `src/components/PanelBar.vue` | panel toggle buttons — compiles, but nothing imports it |
| `src/workers/parser.worker.ts` | streaming JSONL parse off the main thread |
| `src/utils/analytics.ts` | `computeStats()` — P&L, drawdown, MAE/MFE, win rate |
| `src/utils/aggregator.ts` | **empty file**; its tests in `aggregator.test.ts` still describe the intended API (OHLC resampling, fills→candle bucketing) |
| `src/utils/equity.ts` | ACB-based realized P&L curve |

## Known issues

- The `v` event emits `rev`, but `VarUpdate` in `report_types.ts` declares `revision`. Harmless
  today because nothing reads it.
- `Fill.orderId` in `report_types.ts` is camelCase, while the wire sends `order_id` (and `id`).
  Harmless today because only the connected fill-marker code reads price/side/quantity/time.
- Variable namespacing (`BTCUSD::ema_master`) is not yet stripped; the plan is to store settings
  under the bare name so they carry across instruments.
- `src/types/orders.ts` is empty and unreferenced.
