# QuarkBot Viewer — Claude Context

Browser-based backtest report visualizer. Reads `.jsonl` report files generated by `src/quarkbot/backtest/json_report.cpp` and shows an interactive TradingView-style chart.

## Quick start

```bash
cd src/viewer
npm install
npm run dev          # dev server on :5173, proxies /api → :3000
node server.js ../../report.jsonl   # production: random port, prints URL
node server.js report.jsonl -p 3000 # force specific port
```

Build for production: `npm run build` → `dist/`

## Stack

- **Vue 3** + TypeScript + Vite
- **lightweight-charts v4.2.3** — TradingView charting library
- Web Worker for streaming JSONL parse (no UI block)
- Node.js HTTP server (`server.js`) serves `dist/` + `/api/report` endpoint

## JSONL format (events in order)

Each line: `[unix_seconds, sequence, event_type, payload]`

| type | payload | meaning |
|------|---------|---------|
| `I` | `{name, leverage, multiplier, type, tick_scale}` | instrument registration |
| `C` | `{interval}` | base candle interval in seconds |
| `c` | `[name, open, high, low, close, volume]` | OHLC bar (close time = unix_seconds) |
| `f` | `{instrument, order_id, price, quantity, side, reason, label}` | fill event |
| `s` | `{instrument, order_id, filled, turnover, fees, fees_native}` | fill stats summary |
| `v` | (future) | strategy variable snapshot — not yet parsed |
| `o` | (future) | order state — not yet parsed |

## Architecture

```
server.js (/api/report)
    │
    ▼
App.vue (state hub)
 ├── TopBar.vue          instrument select, TF buttons, PanelBar
 │    └── PanelBar.vue   panel toggle buttons (Equity / Volume / ...)
 ├── ChartView.vue       lightweight-charts wrapper, all series
 ├── StatsPanel.vue      220px right panel, per-instrument stats
 └── FillDetail.vue      modal: fill table on candle click
```

### Data flow

1. `App.vue` spawns `parser.worker.ts` via `?worker` import
2. Worker does `fetch('/api/report')` → streams JSONL line by line
3. Worker sends progressive `WorkerMessage` events:
   - `meta` → instrument list + baseInterval (sent after first `I` + `C` event seen)
   - `candles` → chunks of 1000 candles per instrument
   - `fills` → chunks of 500 fills per instrument
   - `progress` → 0–100%
   - `stats` → computed `Stats` object per instrument (sent at end)
4. App.vue accumulates into `candlesMap` / `fillsMap` / `statsMap` (Map<instrument, data>)
5. Reactivity note: Maps must be replaced (not mutated) to trigger Vue reactivity: `map.value = new Map(map.value)`

### Key utilities

| file | purpose |
|------|---------|
| `src/utils/aggregator.ts` | `aggregateCandles(candles, factor)` — OHLC resampling; `groupFillsByCandle(fills, candles)` — fills→candle buckets |
| `src/utils/analytics.ts` | `computeStats(fills, candles, fillStatsMap, meta)` — P&L, drawdown, MAE/MFE, win rate |
| `src/utils/equity.ts` | `computeEquityCurve(fills)` — ACB-based realized P&L time series for equity panel |

### Panel system (ChartView.vue)

lightweight-charts v4.2.3 does NOT support native multi-pane (the `pane` series option is silently ignored). Instead, each panel is a separate `createChart()` instance inside a flex column. Time scales are synchronized via `subscribeVisibleLogicalRangeChange`.

`enabledPanels: string[]` in App.vue — ordered list (equity → volume → ...). Panel divs are always pre-created (`onMounted`) and shown/hidden via `v-show`.

**Adding a new panel:**
1. Add `{ id: 'foo', label: 'Foo' }` to `PANELS` array in `PanelBar.vue`
2. Add a new `ref<HTMLDivElement>` + `ref<IChartApi>` + `ref<ISeriesApi>` in `ChartView.vue`
3. Create the chart in `onMounted`, add it to `syncTimeScale` iteration, observe it in ResizeObserver
4. Add `v-show="enabledPanels.includes('foo')"` div in template
5. Handle data update in relevant `watch()`

Currently registered panels:

| id | type | default | data source |
|----|------|---------|------------|
| `equity` | `BaselineSeries` (green/red from 0) | **ON** | `computeEquityCurve(fills)` — realized P&L |
| `volume` | `HistogramSeries` | OFF | aggregated candles volume |

## Planned next step: variable panels

The `v` event in JSONL carries strategy variable snapshots (not yet parsed). Plan:
- Parse `v` events in `parser.worker.ts`, send as new `WorkerMessage` type `variables`
- Each variable = its own panel entry with dynamic ID like `var:ema_fast`
- Worker discovers variable names dynamically; App.vue collects them; PanelBar renders toggle per variable
- ChartView handles `var:*` panel IDs in `rebuildPanels()` using a `LineSeries` per variable

## Known limitations / notes

- `baseInterval` from `C` event is in **seconds**; TopBar displays it with `m` suffix (treating as minutes) — may need correction if strategy uses non-minute intervals
- Equity curve shows *realized* P&L only (no unrealized); fees not included (fee data is per-order in `s` events, not per-fill)
- Performance: `computeEquityCurve` called on every fill batch update (O(n) but repeated); `groupFillsByCandle` is O(fills × candles/timeframe) — fine for typical backtest sizes
- `setMarkers` requires strictly ascending time order (enforced by sort in `applyMarkers`)
- When `enabledPanels` changes, all indicator series are destroyed and recreated (required — lightweight-charts does not allow moving a series to a different pane)
